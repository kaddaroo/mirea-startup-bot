# Технические решения

## 2026-09-10 — Стек: aiogram 3 (асинхронный) + PostgreSQL

### Почему асинхронность вообще нужна боту

Бот постоянно ждёт: ответа от Telegram, ответа от базы. Пока ждёт — простаивает.
Асинхронность позволяет в это время обрабатывать других пользователей, а не стоять в очереди.

Например: 50 человек одновременно регистрируются на мероприятие — без async бот шёл бы по одному,
с async обрабатывает их параллельно, не блокируясь на ожидании БД.

Рассылка напоминаний — та же история: без async она бы держала весь бот занятым, пока не разошлёт всем.

### Почему aiogram, а не telebot / python-telegram-bot

aiogram изначально спроектирован асинхронным (на asyncio), FSM для
многошаговых сценариев (как наша регистрация) встроен из коробки,
и это самая популярная асинхронная библиотека для Telegram-ботов на Python
сейчас — значит, проще найти примеры и помощь, если что-то не получается.

### Почему PostgreSQL, а не SQLite

SQLite не умеет нормально работать с параллельными записями (а при async-боте
запросы к БД идут параллельно) — будут блокировки. PostgreSQL для этого и
существует, плюс бесплатный и стандартный выбор для таких проектов.
